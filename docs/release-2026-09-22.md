# Image quality and multiplayer fixes

## Image quality

- **Panoramas rendered at a quarter of the sphere on HiDPI screens.** `PanoViewer`
  called `renderer.setSize(w, h, false)`, which sizes the canvas in device pixels
  but leaves it without a CSS size. The canvas element then laid out at
  `width × devicePixelRatio`, and the host clips overflow — so on a 2× phone or
  laptop the player saw only the top-left quarter of the plate, permanently
  zoomed. Measured in Chromium at `deviceScaleFactor: 2`: an 800 × 600 host got a
  1600 × 1200 CSS canvas before, 800 × 600 after, with the 1600 device-pixel
  backing store kept either way.
- Anisotropic filtering now takes the GPU maximum instead of being capped at 8.
  A panorama is viewed at grazing angles almost everywhere, which is where it pays.
- The projection sphere went from 64 × 40 to 128 × 64 segments, so a zoomed-in
  horizon stays a curve.
- **Mapillary plates were capped at 2048 px.** A 2048 px equirectangular image
  spread over a full sphere is about 5.7 px per degree. The provider now requests
  `thumb_original_url`, `thumb_2048_url` and `thumb_1024_url` and displays the
  widest that came back, falling down the ladder when the larger sizes are absent.
- Wikipedia fallback plates are requested at 2560 px rather than 1920 px, matching
  the bundled plates they stand in for.
- `responsiveSceneSrcSet` no longer hard-codes a single filename. Hi-res plate
  pairs are compiled into `src/lib/game/hires-plates.ts` by
  `scripts/build-hires-manifest.mjs`, and a test fails if the manifest drifts from
  `public/locations/hires/`. Adding a plate there now serves it automatically.
  The generated widths match the previous hand-written entry exactly.

## Multiplayer

- **A `wss://` match-server URL was silently downgraded to `ws://`.** The protocol
  mapping only special-cased `https:`, so the documented `https://` origin worked
  but the equally natural `wss://` became a mixed-content URL the browser refuses
  to open from an HTTPS page — online play would never connect. Each scheme now
  keeps its own security level, and an unknown scheme is assumed secure.
- **Commands issued while the socket was down were dropped in silence.** A lock
  sent during a reconnect returned `false` to nobody, so the round expired and
  scored zero. The client now holds them in an outbox (one entry per command
  kind, newest wins) and replays it on reconnect.
- **Replayed and late commands could land on the wrong round.** `pin`, `lock`,
  `intro` and `continue` now carry the `questionIndex` they were made for, and the
  room drops a command the round has moved past — the protection the P2P transport
  already had. The field is optional, so a client that omits it behaves as before.
- **A server-mode lock gave no feedback until the snapshot returned**, and the
  button stayed live long enough to fire a second one. It is now held pending in
  both transports, showing "Sending your guess…" until the server confirms.
- **A dropped match-server connection was invisible mid-match.** The reconnect
  banner only ever read the P2P error channel. One notice now covers both
  transports, and the lobby stops claiming "Waiting for opponent" on a closed socket.
- **A seated guest kept announcing itself forever.** The `hello` heartbeat had no
  stop condition, and the host answers every `hello` with `PLAYER_JOIN` plus a
  full snapshot to the whole room — a state bump, a re-render on both clients and
  a full `sessionStorage` serialisation of the match, every 1.5 s for the entire
  game. It now stops once the host's state actually holds a seat for this player.
- **The Durable Object woke itself for work already done.** `alarm()` applied due
  leaves before persisting the pruned map, and `apply` re-arms from storage — so
  it set an alarm for a deadline that had just fired. The fired deadlines are
  dropped first.
- **`ALLOWED_ORIGIN` was declared in `wrangler.toml` and in `Env` but never read.**
  Setting it did nothing. The upgrade is now refused for a browser origin outside
  the list; the default `*` keeps current deployments open.

## Verification

- `npm run test:game`: 117 passed (103 before), covering the new URL scheme
  mapping, the outbox, question scoping and the hi-res manifest sync.
- `npm run typecheck`, `npm run typecheck:worker`, `npm run lint`,
  `npm run build`: all pass.
- The panorama canvas measurement above was taken in Chromium via Playwright.

## Not covered

The match worker was typechecked but not deployed, so the server-authoritative
path (outbox replay, question scoping, the origin check, the alarm change) is
verified by unit tests and reading, not against a live Durable Object. Two-browser
P2P play was not re-run in this pass. `npm ci` fails on this repository for a
pre-existing lockfile drift (`lru-cache@11.5.3` missing from `package-lock.json`);
`npm install` works, and the lockfile is untouched by this change.
